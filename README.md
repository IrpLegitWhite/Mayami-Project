# Mayami

Компактный язык программирования с собственной виртуальной машиной и компилятором в самодостаточные `.exe`.

Написан с нуля на C++17: лексер, парсер, генератор байткода, стековая VM, оконный UI на WinAPI + GDI, IDE на ImGui + DirectX 11.

---

## Компоненты

| Файл | Что делает |
|---|---|
| **`mayamic.exe`** | Компилятор: `.mayami` → `.myc` / `.exe` |
| **`mayamivm.exe`** | Виртуальная машина: запускает `.myc`, показывает вывод в окне |
| **`mayami.exe`** | IDE: редактор + терминал + сборка + запуск |

## Синтаксис языка

### Комментарии

Однострочные — `// текст до конца строки`.

### Точки с запятой

Точка с запятой `;` — **обязательна в конце выражений** (`x = 5;`, `p("hi");`).

**НЕ ставится** после закрывающей `}` блоков `{ ... }`:
- `fn name() { ... }`
- `if cond { ... }`
- `else { ... }`
- `while cond { ... }`
- `for i in a..b { ... }`
- `loop { ... }`

**Обязательна** после:
- `return value;`
- `break;`
- `continue;`
- любого присваивания (`x = 5;`)
- любого вызова (`p("hi");`)

### Функции

```
fn имя(параметры) {
    тело
}
```

- Параметры — через запятую, без типов.
- Функции без параметров — `fn main() { ... }`.
- Возврат значения — `return value;`.
- Функции без `return` — возвращают `null`.
- Точка входа — **`fn main()`** (обязательна).

### Переменные

- Создаются автоматически при первом присваивании.
- Типизация динамическая.
- Присваивания: `=`, `+=`, `-=`, `*=`, `/=`, `%=`.

**Типы значений:** `int` (int64), `float` (double), `bool`, `string`, `char`.

### Операторы

**Арифметика:** `+`, `-`, `*`, `/`, `%`

**Сравнения:** `==`, `!=`, `<`, `>`, `<=`, `>=`

**Логика:** `&&`, `||`, `!`

**Битовые:** `&`, `|`, `^`, `~`, `<<`, `>>`

**Присваивание:** `=`, `+=`, `-=`, `*=`, `/=`, `%=`

### Управляющие конструкции

```
if условие { ... }
if условие { ... } else { ... }
if условие { ... } else if условие { ... } else { ... }
```

```
while условие { ... }
```

```
for i in a..b { ... }
```

Диапазон `a..b` — **полуоткрытый**: от `a` до `b-1`.

```
loop { ... }
```

Бесконечный цикл. Выход — `break;`.

**`break;`** — выход из ближайшего цикла.

**`continue;`** — следующая итерация ближайшего цикла.

### Литералы

- **Целые:** `42`, `-7`, `1000`
- **Дробные:** `3.14`, `-0.5`
- **Строки:** `"Hello, world!"` (двойные кавычки)
- **Символы:** `'A'` (одинарные кавычки)
- **Логические:** `true`, `false`

## UI-фреймворк

Кастомный оконный UI на WinAPI + GDI. Все функции доступны из Mayami.

### Управление окном

| Функция | Описание |
|---|---|
| `ui_begin(title, w, h)` | Создать окно `w × h` с заголовком `title` |
| `ui_theme(r, g, b)` | Цвет фона окна (RGB 0..255) |
| `ui_width()` | Ширина рабочей области (int) |
| `ui_height()` | Высота рабочей области (int) |
| `ui_running()` | `true` пока окно открыто |
| `ui_show()` | Показать окно (не блокирует) |
| `ui_clear()` | Очистить все элементы |
| `ui_refresh()` | Перерисовать окно |

### Рисование

| Функция | Описание |
|---|---|
| `ui_rect(x, y, w, h, r, g, b)` | Прямоугольник |
| `ui_rect_round(x, y, w, h, radius, r, g, b)` | Скруглённый прямоугольник |
| `ui_text(x, y, text, r, g, b)` | Текст |
| `ui_text_size(x, y, text, size, r, g, b)` | Текст с размером шрифта |

**Координаты** — от левого верхнего угла окна, в пикселях.

**Цвет** — три числа R, G, B в диапазоне 0..255.

**`size`** для `ui_text_size` — в пунктах (типично 12..48).

### Кнопки

| Функция | Описание |
|---|---|
| `ui_button_c(x, y, w, h, text, id, r, g, b)` | Кнопка с цветом |

- **`text`** — надпись на кнопке.
- **`id`** — строковый идентификатор (уникальный). По нему определяется нажатие.
- **`r, g, b`** — цвет в обычном состоянии. При hover — светлее. При нажатии — темнее.

### События

| Функция | Описание |
|---|---|
| `ui_poll()` | Возвращает `id` последней нажатой кнопки (или `""`) |
| `ui_mouse_x()` | X-координата курсора |
| `ui_mouse_y()` | Y-координата курсора |
| `ui_sleep(ms)` | Пауза в миллисекундах |

**`ui_poll()`** сбрасывает событие после чтения — следующий вызов вернёт `""`, если новых кликов не было.

**`ui_sleep(16)`** в конце цикла — обязателен для ~60 FPS. Без него — 100% CPU.

### Event loop

Стандартный цикл программы с UI:

```
ui_begin(...)
while ui_running() {
    c = ui_poll()
    // обработка c
    ui_sleep(16)
}
```

При каждом клике — сравнение `c` с `id` кнопок и выполнение логики.

### Перерисовка

UI **не обновляется автоматически**. Для отображения изменений нужно:

1. `ui_clear();` — стереть все элементы.
2. Заново вызвать все `ui_*` — нарисовать новое состояние.

Или рисовать элементы **один раз** в начале (если ничего не меняется).

## Debug-режим

При включённом debug (`Ctrl+Shift+F5`) в **BUILD** вкладке терминала выводится **пошаговый trace VM**:

| Поле | Значение |
|---|---|
| `#N` | Номер шага |
| `ip` | Instruction pointer (адрес в коде) |
| `op` | Hex-код опкода |
| `(NAME)` | Символическое имя опкода |
| `stack=N` | Размер стека операндов |
| `vars=N` | Размер массива переменных |
| `frames=N` | Глубина стека кадров |

Дополнительно логируются:
- `LOAD_VAR` / `STORE_VAR` — со `slot`, `base`, `real`, `vars_size`.
- `CALL` — с `funcIdx`, `argc`.
- `JUMP` / `JUMP_IF_*` — с адресом перехода.
- `CALL_NATIVE` — с `id`, `argc`.
- `UI_POLL` — с возвращённым `id`.
- `POP-EMPTY` — при попытке `pop()` на пустом стеке.

## Ошибки компиляции и времени выполнения

### Ошибки лексера

Формат: `Lexer error at line N, col M: <текст>`

Причины:
- Недопустимый символ (`Unexpected character 'X'`).
- Битый файл (ZIP, UTF-16, BOM).

### Ошибки парсера

Формат: `Parser error at line N, col M: <текст>`

Причины:
- Пропущенный `;`.
- Лишний `;` после `}`.
- Несовпадение скобок.
- Неверный синтаксис.

### Ошибки генератора байткода

Формат: `[ERROR] <текст>`

Причины:
- Нет `fn main()`.
- Обращение к необъявленной переменной в строгом режиме.
- Неизвестный оператор.

### Ошибки VM

Формат: `[ERROR] <текст>`

Причины:
- `Stack underflow` — попытка `pop()` на пустом стеке.
- `Division by zero` — деление на 0.
- `Modulo by zero` — `% 0`.
- `Array index out of bounds`.
- `JUMP out of bounds` — переход за пределы кода.
- `CALL: invalid funcIdx` — вызов несуществующей функции.
- `Stack overflow` — стек > 100 000.

### `Stack underflow` — что это

Возникает, когда VM пытается снять со стека больше, чем было положено.

Причины:
- Ошибка в сгенерированном байткоде.
- Некорректный `.myc` файл.
- Баг в `BytecodeGen`.

Восстановление: `pop()` на пустом стеке возвращает `null`, а не падает. В лог пишется ошибка.

## Формат `.myc`

Структура бинарного файла:

```
BytecodeHeader (32 байта)
    magic         uint32   "MYMI" (0x4D594D49)
    version       uint16   1
    reserved      uint16   0
    codeSize      uint32   размер кода
    constSize     uint32   размер пула констант
    funcCount     uint32   количество функций
    structCount   uint32   количество структур
    entryPoint    uint32   адрес входа (обычно 0)

Constant Pool
    [4 байта длина][N байт данных] × constSize

Function Table
    BytecodeFunction × funcCount
        nameOffset   uint32   смещение имени в пуле строк
        codeOffset   uint32   смещение кода функции
        localCount   uint32   количество локальных переменных
        paramCount   uint8    количество параметров
        reserved     uint8[3]

Code
    Байткод (опкоды + аргументы)
```

Все числа — **little-endian**.

## Формат `.exe` (самодостаточный)

Копия `mayamivm.exe` + байткод в хвосте + трейлер.

**Трейлер (последние 12 байт):**

| Смещение | Размер | Значение |
|---|---|---|
| 0 | 4 | Magic `0x4D594D49` (`MYMI`) |
| 4 | 4 | Размер байткода |
| 8 | 4 | Зарезервировано (0) |

При запуске `.exe` читает **сам себя**, находит трейлер, извлекает байткод и исполняет.

## Управление памятью

- **Стек операндов** — `std::vector<VmValue>`. Растёт/падает автоматически.
- **Массив переменных** — `std::vector<VmValue>`. Растёт при `STORE_VAR`.
- **Стек кадров** — `std::vector<Frame>`. `CALL` push, `RET` pop.
- **Массивы и структуры** — `std::shared_ptr`, счётчик ссылок.

**Ограничения:**
- Стек > 100 000 элементов — ошибка `Stack overflow`.
- Массив переменных > 100 000 — ошибка `Vars overflow`.
- Стек кадров > 10 000 — ошибка `Frames overflow`.

## Семантика

### Область видимости

- **Локальные переменные** — внутри функции.
- **Параметры** — локальные переменные.
- **Глобальные переменные** — не реализованы. Переменные видны только внутри своей функции.
- Из `main` переменные **не видны** внутри других функций.

### Возврат значений

- Функция без `return` возвращает `null`.
- Функция с `return` без значения — тоже `null`.
- `return value;` возвращает значение любого типа.

### Рекурсия

- **Поддерживается**, включая непрямую (через другие функции).

### Строки

- Иммутабельные. Любая операция возвращает **новую** строку.
- Конкатенация — оператор `+`.
- Сравнение — `==`, `!=` (по содержимому).
- Длина — в **символах**, не в байтах.

### Числа

- **Целые** — 64-битные знаковые (`int64_t`).
- **Дробные** — 64-битные (`double`).
- **Смешанные операции** — `int` автоматически становится `float`, если хоть один аргумент — `float`.
- Деление `int / int` — **целочисленное** (отбрасывает остаток). Для дробного — используй `float`.

### Логические

- `true`, `false` — булевы значения.
- В условиях — `null`, `0`, `""` → `false`; остальное → `true`.

**Не реализовано:**

- `int(str)` / `str(num)` / `float(str)` — преобразования типов.
- Файловые операции (`open`, `read`, `write`, `close`).
- Модули и импорты.
- Аннотации типов (парсятся, но игнорируются).
- Многопоточность.
- Замыкания.
- Исключения.

**Реализовано и работает:**

- Функции, рекурсия, параметры, возврат.
- Переменные всех типов.
- Все операторы (арифметика, сравнения, логика, биты).
- Условия, циклы `while` / `for` / `loop`.
- `break` / `continue`.
- Математика (11 функций).
- Строки (7 методов).
- Полноценный UI (окна, кнопки, тексты, прямоугольники).
- Event loop (`ui_running` + `ui_poll`).
- Компиляция в `.myc` и самодостаточный `.exe`.

## Технические детали VM

### Стек операндов

LIFO-структура. Все вычисления — через push/pop.

### Кадры вызовов

При `CALL`:
1. Сохраняется `returnIP` (адрес возврата).
2. `varBase = m_vars.size()` (база локальных).
3. `m_vars.resize(varBase + localCount)` — выделение места.
4. Параметры копируются в `m_vars[varBase + 0..argc-1]`.
5. `m_ip = fn.codeOffset` — переход в код функции.

При `RET`:
1. Снимается возвращаемое значение со стека.
2. `m_vars.resize(frame.varBase)` — освобождение локальных.
3. `m_ip = frame.returnIP` — возврат.
4. Возвращаемое значение кладётся на стек вызывающей стороны.

### Оптимизации

- Пул строк — интернирование констант.
- Прыжки с патчингом — двухпроходная генерация.
- Вектор констант — прямой доступ по offset.
- Никаких аллокаций на каждой операции (кроме строк и коллекций).

## Формат вывода `p(...)`

- Принимает 0+ аргументов.
- Каждый аргумент → строка через `toString()`.
- Аргументы разделяются **одним пробелом**.
- После — **новая строка**.

**Конвертация значений в строку:**

| Тип | Как выводится |
|---|---|
| `null` | `null` |
| `int` | `42`, `-7` |
| `float` | `3.14`, `0.5` (с `%g`) |
| `bool` | `true` / `false` |
| `string` | как есть |
| `char` | один символ |
| `array` | `[1, 2, 3]` (пока не работает) |

## Известные проблемы

- `std::filesystem::create_directories` в MSVC иногда падает на длинных путях → заменён на WinAPI (`CreateDirectoryA`).
- `_popen` ломается на кавычках в путях → заменён на `CreateProcessA`.
- Файлы `.mayami`, созданные через Проводник «Создать → Архив», становятся ZIP-архивами → лексер не может их прочитать.
- IDE **не сохраняет в UTF-8 без BOM автоматически** при редактировании в сторонних редакторах.

---

## Работа с файлами `.mayami`

Правильное создание:
- **Через IDE** (`mayami.exe`): `Ctrl+N` → `Ctrl+S` → сохранить как `.mayami`.
- **Через PowerShell** с `[System.IO.File]::WriteAllText(..., [UTF8Encoding]::new($false))`.

Неправильное:
- Проводник → «Создать → Текстовый документ» → переименовать в `.mayami`.
- Блокнот → Сохранить как → без указания UTF-8.
- `echo` в cmd (cp866).
